# Security Dashboard and Alerts

**Module 4** is the **Security Dashboard**. It gives personnel and security a focused view of alerts and incidents so they can monitor the facility and respond quickly.

## Purpose

- Central place for **security and safety-related alerts**
- **Faster response** than scanning the full activity log
- Can combine inputs from crowd, environment, feedback, and any security-specific sensors or rules

## What you see

- **Active alerts:** List or cards of current incidents (e.g. anomaly, offline module, maintenance report, safety trigger)
- **Severity or priority:** So critical items can be handled first
- **Time and source:** When it happened and which module or rule raised it
- **Details:** Short description or link to full log entry

## Who can access

- Only **logged-in personnel** with the right role (e.g. security or admin).
- Guests do not see the Security Dashboard.

Access is typically from the Personnel Dashboard (link or tab to “Security” or “Module 4”).

## How to respond

1. **Review** new alerts on the Security Dashboard.
2. **Click or open** an alert for full context; use the main activity log if you need the full event stream.
3. **Act** according to your facility’s procedures (e.g. send staff, call maintenance, clear false alarms).
4. **Acknowledge or close** alerts when handled (if the system supports it).

For the full event history and non-security events, use [Alerts and Logs on the Personnel Dashboard](/knowledge-base).
